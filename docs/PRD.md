# 景区传说有声连环画生成器 · PRD

- **版本**:v0.1(草案)
- **日期**:2026-07-07
- **文档状态**:待评审

---

## 1. 产品概述

### 1.1 一句话定义

用户输入一个景区名称,系统自动检索该景区的历史传说,改编为剧本,生成分镜与角色设定,批量绘制连环画页面,并配上解说与配乐,最终输出一部可播放、可分享的**有声连环画视频**。

### 1.2 产品背景与价值

- **供给侧**:几乎每个景区都有传说故事,但绝大多数只以景点石碑、导游口述、百科词条的形式存在,呈现形式陈旧,传播力弱。
- **需求侧**:游客(尤其亲子家庭)在游前种草、游中讲解、游后回味三个环节,都缺乏一个"好看又好听"的故事载体。
- **技术窗口**:LLM 剧本改编 + 可控图像生成(角色一致性)+ TTS + 自动音视频合成,四个环节均已具备工程可行性,组合成流水线即是产品。

### 1.3 产品形态(MVP)

Web 应用。输入景区名 → 分步生成、可干预 → 输出 MP4 视频(有声连环画)+ 图文版(可导出图片序列/PDF)。

---

## 2. 目标用户与核心场景

| 用户角色 | 场景 | 诉求 |
|---|---|---|
| 亲子家长 | 出游前/后给孩子讲景区故事 | 一键生成,画风可爱,解说童声 |
| 文旅内容创作者 | 为公众号/小红书/抖音产出景区故事内容 | 画风可选、文案可改、成品可商用 |
| 景区/文旅局运营方 | 官方宣传物料、导览屏播放 | 内容准确、可审校、批量生产 |
| 研学/导游机构 | 讲解辅助素材 | 史实与传说区分标注 |

**MVP 优先服务前两类个人用户**,B 端能力(批量、审校流、私有素材库)放入后续版本。

---

## 3. 核心流程总览

```
输入景区名
    │
[S0] 传说检索与甄别 ──→ 候选故事列表(用户选一个)
    │
[S1] 剧本改编 ──→ 结构化剧本(幕/场/旁白/台词)
    │
[S2] 分镜设计 ──→ 分镜表(每格:画面描述/镜头/出场人物/文案)
    │
[S3] 角色设定 ──→ 角色特征卡 + 三视图(正/侧/背)
    │                    │
    │              (三视图作为参考图,锁定角色一致性)
    │                    ↓
[S4] 连环画页生成 ──→ 每页画面 + 排版文字
    │
[S5] 配音与配乐 ──→ 每页解说音频 + 全片背景音乐
    │
[S6] 合成输出 ──→ MP4 有声连环画 / 图片序列 / PDF
```

**关键产品原则:每一步生成后允许用户预览、修改、重新生成,再进入下一步。** 全自动一键到底作为"快速模式"提供,但默认走分步确认,因为上游一格分镜的错误会在下游被放大成整页重画的成本。

## 4. 功能需求

### F0 传说检索与故事甄别

| 项 | 说明 |
|---|---|
| 输入 | 景区名称(支持模糊搜索、别名,如"雷峰塔/西湖雷峰塔") |
| 处理 | 通过联网检索 + LLM 整理,产出 2~5 个候选传说,每个包含:标题、200 字梗概、来源类型(正史/地方志/民间传说/文学作品)、来源链接 |
| 输出 | 候选故事卡片列表,用户选择其一进入改编;也允许用户粘贴自备故事文本 |
| 规则 | ① 必须标注"传说"与"史实"属性,不得将传说包装为史实;② 检索不到可靠传说时明确告知,并提供"基于景区特征原创一个故事"的降级选项(输出物需水印标注"原创演绎");③ 涉及宗教、民族、近现代政治人物的传说,进入敏感审校清单 |
| 验收 | 输入 20 个知名景区,≥90% 能返回至少 1 个有据可查的传说;来源链接可访问 |

### F1 剧本改编

| 项 | 说明 |
|---|---|
| 输入 | 选定的传说文本 + 用户参数(目标时长 1/3/5 分钟、受众:儿童/大众、基调:温情/奇幻/悬疑) |
| 处理 | LLM 将传说改编为结构化剧本 |
| 输出 | JSON 结构:`{ 标题, 主题句, 幕[ 场[ 场景描述, 出场角色, 旁白, 对白[] ] ], 角色列表[姓名, 身份, 性格, 外貌关键词] }` |
| 规则 | 儿童向自动规避暴力/恐怖细节;保留传说核心情节,不魔改结局(除非用户勾选"自由改编") |
| 交互 | 剧本以可编辑文档呈现,用户可改任意文字后锁定 |
| 验收 | 剧本幕场结构完整、角色列表与正文一致、字数命中目标时长 ±20% |

### F2 分镜设计

| 项 | 说明 |
|---|---|
| 输入 | 锁定的剧本 |
| 处理 | LLM 按剧本切分分镜,MVP 采用**一页一格**的连环画范式(不做单页多格,降低排版与生成复杂度) |
| 输出 | 分镜表,每格字段:`序号 / 对应剧本场次 / 画面描述(构图、景别、光线、氛围)/ 出场角色 / 页面文案(旁白或对白,≤80字)/ 情绪标签(供配乐用)` |
| 数量 | 1 分钟成片约 8~10 页,3 分钟约 20~24 页,5 分钟约 32~40 页 |
| 交互 | 分镜以卡片列表呈现,支持:改文案、改画面描述、增删页、拖拽排序 |
| 验收 | 分镜文案连起来能独立讲通故事(不看图也能听懂,这是"有声"的底线要求) |

### F3 角色设定与三视图

| 项 | 说明 |
|---|---|
| 输入 | 剧本中的角色列表 + 用户选定的整体画风(MVP 提供 3 种预设:国风水墨 / 儿童绘本 / 现代插画) |
| 处理 | ① LLM 生成角色特征卡(外貌、服饰、道具、色彩方案,落成可复用的 prompt 片段);② 图像模型生成每个角色的**三视图**(正面/侧面/背面,同一张图内,白底,全身) |
| 输出 | 角色特征卡 + 三视图图片,作为后续所有页面生成的**角色参考图** |
| 交互 | 每个角色可单独重绘/局部调整描述后重绘;用户确认后角色锁定 |
| 规则 | 主要角色 ≤4 个(超出的次要角色仅用文字特征约束,不做三视图),控制成本与一致性难度 |
| 验收 | 三视图三个视角为同一角色(人工评估通过率 ≥80%);特征卡 prompt 片段在后续页面中可直接复用 |

### F4 连环画页生成

| 项 | 说明 |
|---|---|
| 输入 | 分镜表 + 角色三视图(参考图)+ 画风预设 |
| 处理 | 逐页生成:`页面 prompt = 画风统一前缀 + 该页画面描述 + 出场角色特征片段`,并以三视图作为图像参考(image reference / 角色一致性通道),固定风格参数 |
| 输出 | 每页:画面图(统一比例,建议 16:9 用于视频 / 3:4 用于图文导出)+ 底部文案区(程序排版,不让模型画字——**模型生成的中文文字不可控,文字一律后期排版叠加**) |
| 交互 | 页面网格预览;单页支持:重绘、微调描述后重绘、上传替换 |
| 验收 | 同一角色跨页可辨认为同一人(抽样人工评估 ≥75%,这是本产品最难指标,见 §8 风险);单页生成失败自动重试 ≤2 次 |

### F5 配音与配乐

| 项 | 说明 |
|---|---|
| 输入 | 每页文案 + 情绪标签 + 用户选项(音色:童声/女声/男声/说书人;语速) |
| 处理 | ① TTS 逐页合成解说音频,记录每页时长;② 按全片主情绪从**授权音乐库**选取背景音乐(MVP 不做 AI 生成音乐,用曲库更稳、版权干净),自动做音量 ducking(人声出现时压低 BGM) |
| 输出 | 每页音频文件 + 全片 BGM 方案 |
| 交互 | 逐页试听;支持改文案后重合成单页;BGM 可换曲 |
| 验收 | 中文多音字准确率抽检 ≥95%(景区人名地名是重灾区,需要支持用户标注读音);人声与 BGM 响度符合 -16 LUFS 左右的常规标准 |

### F6 合成与输出

| 项 | 说明 |
|---|---|
| 处理 | 按"每页时长 = 该页解说音频时长 + 0.5s 缓冲"拼接;页面切换加简单转场(淡入淡出);可选 Ken Burns 效果(画面缓慢推拉)提升观感 |
| 输出 | ① MP4(1080p,16:9);② 图片序列 ZIP;③ 图文 PDF;均带片头(景区名+故事名)与片尾(来源标注 + "AI 生成"水印) |
| 规则 | AI 生成内容标识为合规硬性要求,不可关闭 |
| 验收 | 3 分钟成片端到端(快速模式)生成时间 ≤15 分钟;音画同步误差 <200ms |

## 5. 关键技术方案

| 环节 | 方案 | 备注 |
|---|---|---|
| 传说检索 | 搜索 API + LLM 归纳,强制引用来源 | 用检索结果约束生成,降低编造传说的幻觉风险 |
| 剧本/分镜/角色卡 | LLM(结构化输出,JSON Schema 约束) | 三步共用一条上下文链,保证角色/情节自洽 |
| 三视图 & 页面绘制 | 支持参考图的图像生成模型;角色一致性 = 三视图参考 + 特征 prompt 片段 + 固定风格前缀 | 一致性是全项目最大技术风险,方案上要预留"换模型"的抽象层 |
| 页面文字 | 程序排版叠加(不让模型画字) | 铁律 |
| TTS | 商用 TTS API,支持 SSML 标注多音字 | |
| 配乐 | 授权曲库 + 情绪标签匹配 | MVP 不做 AI 作曲 |
| 合成 | FFmpeg 流水线(图片+音频+转场+字幕轨) | 无状态、可重跑 |
| 任务编排 | 异步任务队列,每步产物落库,支持断点续跑与单步重做 | 分步可干预的产品形态决定了必须做成 pipeline 而非一次性调用 |

## 6. 非功能需求

- **成本可控**:单个 3 分钟项目的推理成本需核算并设上限(约 20~24 页图 + 重绘余量 ×1.5 + TTS + LLM);超限时提示用户而非静默烧钱。
- **可重入**:任何一步失败或用户中途离开,项目状态可恢复。
- **内容安全**:文生图输入输出双侧过滤;宗教/民族题材走人工审校白名单(B 端)或保守模板(C 端)。
- **版权**:曲库需商用授权;输出物注明"传说来源"与"AI 生成"标识;用户上传的自备故事由用户承诺权利。

## 7. MVP 范围与迭代规划

**MVP(第 1 期,建议 6~8 周)**
- 单条流水线跑通:检索→剧本→分镜→角色三视图→页面→TTS→曲库配乐→MP4。
- 3 种画风预设、4 种音色、一页一格、主要角色 ≤4。
- 分步确认 + 快速模式两种流程。

**第 2 期**
- 单页多格分镜、更多画风、角色库复用(同一角色跨项目)、多语言解说、PDF 精排版。

**第 3 期(B 端)**
- 批量生产、审校工作流、私有素材库(景区实拍图融入画面)、导览屏投放格式。

## 8. 风险与难点(按严重度排序)

1. **角色跨页一致性**——最大技术风险。即便有三视图参考,当前图像模型在服饰细节、脸部特征上仍会漂移。对策:① 限制主要角色数量;② 画风选择上偏向"符号化/绘本风"(人物越写实越容易穿帮);③ 提供单页重绘兜底;④ 验收指标定在 75% 而非 100%,并在产品预期管理上诚实。**如果内测中该指标长期低于 60%,应考虑把产品重心从"连环画"退到"插画+有声书"形态(每页画面独立成立,不强依赖角色复现)。**
2. **传说的真实性与敏感性**——LLM 会编造"看起来像传说的故事"。对策:检索结果强约束 + 来源必须可点击 + 传说/史实标签,原创演绎必须显式标注。
3. **中文 TTS 多音字/专名读音**——景区名、古人名读错会直接摧毁产品可信度。对策:SSML 读音标注入口 + 常见景区专名读音词典。
4. **成本结构**——图像生成是大头,重绘率直接决定毛利。需要在内测阶段统计真实重绘率来定价。
5. **版权边界**——部分"传说"实为当代文学作品改编(如某些景区的现代 IP 故事),需在检索甄别阶段识别来源类型并规避。

## 9. 整体验收标准(MVP 出口条件)

1. 选 10 个知名景区(如雷峰塔、黄鹤楼、日月潭、华清池等)端到端各生成一部 3 分钟成片,全部成功产出。
2. 角色一致性人工评分 ≥75%,分镜文案"只听不看能懂"通过率 100%。
3. 快速模式端到端 ≤15 分钟;分步模式每步等待 ≤90 秒(页面生成除外)。
4. 全部输出物带来源标注与 AI 生成标识。
